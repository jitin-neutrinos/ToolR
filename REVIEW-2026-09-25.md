# tool-router — Extensive Review (2026-09-25)

Scope: all of ~/Work/tool-router (2,724 lines: router_core 916, route 229, install 496,
selftest 243, dense_index 125, laya_rerank 101, gate 95, session_card 54, index_build 56).
Method: full source read, 14/14 selftest run, 18 live queries through the real pipeline,

## Verdict

Solid core, honest failure posture, one structural bug that quietly throws away most
of the value the dense lane and Laya rerank add, plus one latency problem. The bug is
fixable in ~20 lines. Details below, ranked.

---

## P0 — Score-scale collapse: dense-only hits can never make the card

`route.py:card_for()` rescales fused RRF scores with `row["score"] = fused_score(key)*10`
("rescale into card range"). But RRF scores are rank-based and tiny: one lane contributes
1/61 ≈ 0.0164, so the ceiling for a pure-semantic hit is ~0.33 (both lanes) or 0.16
(dense only). Meanwhile BM25 relative scores run 0.3–2.5, and `min_score = 0.28`.

Consequence, proven live on "whatsapp style voice note transcription":

- dense lane ranks `whisper` **#1** (correct — it IS the right skill)
- whisper has zero BM25 vocabulary overlap (`transcription` doesn't stem to
  `transcribe`), so BM25 never scored it at all
- fused score for whisper = 0.164 → **below the 0.28 floor** → cut by `select()`
- card the model sees: `humanizer`. Wrong.

The project's own research-stage1-verdict.md says the whole point of hybrid is:
"If the right skill isn't in BM25's shortlist, Laya never sees it." The implementation
reintroduces exactly that failure at the final gate: the dense lane can reorder the
shortlist but can never ADD a BM25-missed skill to the card. Recall gains discarded.

Also verified: the same scale mismatch nullifies Laya. On that query Laya reranked
`songwriting-and-ai-music` to front, but its fused score (0.156) fell below the floor,
so `select()` surfaced humanizer anyway. Three layers, three different answers, card
shows the wrong one.

Fix (smallest correct shape): stop rescaling. Keep BM25 relative score as the primary
key; give dense-ranked items a bounded additive boost (e.g. `+0.15 × (1 - rank/50)`), OR
give pure-semantic hits their own quota: top-2 dense-only candidates appended to the
card labeled "semantic match" without needing to clear min_score. Either fits in ~15 lines.

## P0 — Straggler rows bypass fusion on a different scale

route.py:131-137: BM25 rows cut by fusion are appended to `merged` with their ORIGINAL
raw relative score (1.0–2.5 range) while fused rows carry 0.16–0.33. `select()` then
applies one 0.28 threshold to a list holding two incompatible scales: stragglers sail
through at raw BM25 strength, fused rows get judged on the RRF scale. Not a reorder bug
(list order is preserved) but it makes the threshold meaningless per-row.

## P1 — Laya rerank costs ~0.9–1.1 s on EVERY prompt, for override-able value

Measured: full hook path 1.0–1.05 s warm; breakdown: BM25 3 ms, dense 5–100 ms,
Laya 820–1130 ms with 10 candidates × 2 questions (a 1-candidate probe to the same
endpoint: 115 ms — cost scales with candidate count). Laya changed the winner on 3/12
live queries, and one of those changes was wrong (songwriting for a transcription
request — see P0 cascade).

Cheapest wins, in order:
1. Skip the `needs_tool` question entirely — its answers hovered 0.42 across all
   probes (no signal) and its output (`laya_no_tool`) is never rendered on the card.
2. Send top-5 candidates, not 10 (should roughly halve latency).
3. Conditional rerank: only fire when fusion and BM25 disagree or top fused scores are
   within epsilon (the cases reranking can actually settle). Estimated: Laya fires on
   a minority of prompts, average added latency drops under 200 ms.
4. Or hard timeout 0.5 s instead of 2.0 — a slow Laya answer is not worth more than
   the BM25 answer it would replace.

## P1 — Circuit breakers are process-local, so they never persist

`dense_index._DOWN_UNTIL` / `laya_rerank._down_until` are module globals. Every hook
invocation is a fresh python process, so the 60 s breaker only protects within a single
route. When Laya is down, EVERY prompt pays the full `timeout_s: 2.0`; same shape for
Ollama (20 s first-fail timeout — though embed default 8 s at query time). Fix: stamp a
breaker file (e.g. `~/.tool-router/breaker.json` with service+until-timestamp) — 6 lines.

## P1 — The newest, most complex code path has zero test coverage

The RRF fusion block lives inline in `card_for()` (route.py ~L81-137). Neither
selftest.py (14 tests) nor test_hybrid.py (dense alignment only) touches it. This is
where both P0 bugs live. Fix: extract `fuse(bm25_rows, dense_hashes, index) -> rows`
into router_core, port the block, add one test asserting (a) a dense-only top-1
survives select(), (b) scales are comparable across merged rows.

## P2 — Enforcement gate is latent-broken (not currently wired, so dormant)

`--enforce` was never run on this machine (advice-only mode; confirmed: no gate.py in
~/.claude/settings.json). But gate.py's deny-once logic keys on `prompt_id`, and
Claude Code's UserPromptSubmit payload has no prompt_id field — route.py always stores
`""`. First deny sets `denied_for=""`, which then equals EVERY later prompt's
`prompt_id`, so the gate can fire at most once per state file lifetime, not once per
prompt. Fix before ever enabling --enforce: key on a hash of the prompt text (route.py
has it) when payload lacks prompt_id.

## P2 — Dead config + doc drift

- `laya_rerank.min_confidence` (config.json: 0.5; module docstring says 0.55) is never
  read — rerank hardcodes `margin < 0.10 and p1 < 0.75`. Either wire the key or delete it.
- README says "13 assertions"; selftest has 14.
- config.json lives in the repo AND at ~/.tool-router/config.json; repo copy also
  carries laya_rerank — the deployed copy only needs what differs from defaults.

## P2 — State file races (minor, advisory-only today)

`~/.tool-router/last_route.json` is a single global file. Claude hook, opencode plugin
and Hermes all write it; concurrent harnesses overwrite each other's
needs_skills/picks. Harmless while enforcement is off; breaks meaningfully if gate is
ever enabled on two harnesses at once. Fix if ever needed: filename includes harness
env var.

## P2 — Detached-rebuild stampede (tiny)

`get_index()`: foreign cwd or stale index spawns one detached index_build per route
until a rebuild lands (~210 ms build). 5 rapid foreign-cwd routes spawned 5 builders.
Fix: spawn only if no builder PID file / builder younger than N seconds. Cosmetic.

## Positive findings (keep)

- Failure posture is exemplary: every external dep (Ollama, Laya, numpy) fail-open,
  routing always exits 0, malformed skills never kill the index build.
- ML hygiene above hobby grade: margin-gated rerank instead of raw argmax, GENERIC
  term damping, language/ecosystem demotion, content-hash embedding cache (737/741
  reused), single normalization function discipline (norm() with the alias table).
- Token cost awareness: repeat compaction (verified working — second identical route
  returns a 3-line card), 6000-char hard cap, sub-threshold silence.
- Performance: 56 ms full index build, 3 ms BM25 score, 33 ms discovery over 8
  harness roots, ~1.15 MB dense index. Fine.
- README "Honest limits" section is genuinely honest — matches observed behavior.
- Edge battery: None-safe tokenizer, emoji/CJK handled, 500 KB prompt tokenizes in
  ms, regex-hostile input no ReDoS, hostile frontmatter ignored gracefully. One leak:
  `/review-pr 123 fix auth please` (4+ words) routes — slash commands with long args
  get a card. Defensible; noting it.
