## Found broken during review — both FIXED

### 1. Dense lane dead: Ollama serving an empty models dir (root cause found)

Symptom: live route cards showed no `[semantic]` tags; `/api/tags` returned `{"models":[]}`;
embedding calls 404 (`model "nomic-embed-text" not found`).

Root cause chain:
- Models were **moved** to `/mnt/work/models/ollama` (intact: 12 models, 32 blobs, 50G,
  manifests for nomic-embed-text present; `/mnt/work` is fstab-mounted with nofail).
- The listening server (PID 4153) was **spawned by openviking-server (PID 2053) as a child
  process at 17:47 on 09-25** with no `OLLAMA_MODELS` set → served default `~/.ollama/models`,
  an empty dir created that same second. So "ollama is up, models dir empty" was literal.
- Second stray: root-owned `ollama serve` (PID 4792) inside a docker container (containerd
  shim parent) — lost the port race, harmless, left alone.
- Silent-failure amplifier: `~/.ollama/models` metadata was current with `built_at` fresh and
  `ok:true` because build_dense **reuses** old vectors by content hash and only fails when it
  needs a NEW embedding — so the 07:15 rebuild looked successful while attempting 0 embeddings.
- Breaker asymmetry (minor): `_trip()` writes `breaker-ollama.json`, but `_embed` returns early
  on the 404 response path without tripping (only connection-level exceptions trip). File only
  appeared after direct module probing.

Fixes applied:
- New `~/.config/systemd/user/ollama.service` (enabled, running since 07:26):
  `OLLAMA_MODELS=/mnt/work/models/ollama`, `OLLAMA_HOST=127.0.0.1:11434`, Restart=always.
  Stray user-space server killed; the docker stray left (no port access).
- Dense index rebuilt: `6 embedded, 741 reused`. Live routes now carry `[semantic]` tags.
- Semantic-value proof: "make the page feel snappier when scrolling" (zero shared vocab with
  any skill name) → locomotive-scroll 1.317 / framer-motion-scroll 1.236, both `[semantic]`.
  That is the exact case lexical-only routing loses, now working.
- Breakers cleared (ollama, rewriter, laya). All three files absent = all lanes armed.

### 2. Laya rerank timeout too tight (open, needs a number change)

- Endpoint is healthy: `/v1/systemone` returned 200 with `predict ms=829.4` at 07:28.
- Router client timeout is `timeout_s: 0.6` → the client hangs up at 600ms, gets a
  client-side error, trips `breaker-laya.json` for 60s. So rerank mostly sits out under load,
  by design fail-open — but then the "margin-gated Laya rerank" stage is effectively dormant
  whenever predictions run ~800ms.
- Recommended: raise `~/.tool-router/config.json` → `laya_rerank.timeout_s` to 1.5.
  Cost: worst case +1.5s on the fast path only when Laya is slow-but-alive (breaker still
  caps repeat cost at one attempt per 60s). NOT applied — config change is yours to approve.
